# M3 + M4 implementation decisions

## Acquisition and OCR

FactoryFlow supports manual entry, pasted WhatsApp text, gallery images, shared text, and shared images. Direct camera acquisition and CameraX are intentionally excluded.

Image recognition is exposed through the authenticated `POST /api/ocr/recognize` endpoint. The Spring Boot `OcrProvider` boundary delegates to the private Python runtime in `backend/ocr-runtime`, which runs PaddleOCR 3.x with the French PP-OCRv5 pipeline. The runtime applies EXIF orientation and a safe maximum-edge downscale. It does not threshold, persist, or forward images to a cloud service. Uploads are limited to JPEG, PNG, or WebP and ten MiB by default. The API returns full text, ordered lines, confidence, bounding boxes, engine identity, processing time, and warnings.

OCR performs transcription only. Its output enters the same deterministic parser used by pasted text and can never bypass explicit human review. Low recognition confidence is an attention signal, not an automatic rejection.

The normal test suite uses a provider double and never downloads or initializes OCR models. `ocr-runtime/qa` contains separate expected transcriptions, deterministic fixture generation, and an opt-in runner for a locally provisioned PaddleOCR runtime. No OCR accuracy claim is made until that runner has been executed on the target environment and its raw results preserved.

## Analytics semantics

`ReportAnalyticsService` is the sole analytics implementation used by Statistics and document generation. It reads confirmed reports only, preserves a genuine zero, excludes missing values from numeric calculations, and reports valid/missing counts and completeness explicitly. It computes latest, mean, minimum, maximum, range, population standard deviation, previous-equivalent-period mean delta, first/last values, and a least-squares trend.

A trend requires at least two valid observations. The trend is stable when the absolute regression slope is at most one percent of the absolute period mean per observation, with a numerical floor of `0.000001`. Otherwise it is increasing or decreasing. Insufficient samples remain `INSUFFICIENT_DATA`; no value is invented.

## Documents and schedules

PDF and Excel documents contain confirmed data only. Excel has `Synthèse`, `Données`, `Analyse KPI`, `Qualité des données`, and `Traçabilité`; missing numeric cells remain blank. The analysis sheet contains a native POI chart. Weekly and monthly PDF reports include an executive analytics section. Stored filenames are generated by the backend, versioned, and sanitized again by Android before local sharing.

Quartz uses `Africa/Casablanca`. Duplicate schedule/period/format execution is prevented by database uniqueness and the run state service. Generation failure does not publish a ready document. E-mail failure is recorded independently from successful file generation.

## Notifications

M3/M4 deliberately implements durable in-app notifications instead of claiming FCM real-time delivery. Confirmed reports, successful scheduled generation, schedule failure, and scheduled e-mail failure create user-scoped notifications. FCM remains a future deployment enhancement; the application does not present a fake real-time state.
